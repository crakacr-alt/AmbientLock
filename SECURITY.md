# Security Policy

AmbientLock v0.1 — исследовательский developer tool, а не security sandbox.

## Что проект защищает сейчас

Он помогает обнаруживать новые ambient capabilities между двумя запусками.
Например, новая версия программы начала читать дополнительный файл или обращаться
к новому endpoint.

## Что проект НЕ обещает

- syscall не блокируется до выполнения;
- parser не покрывает все Linux syscalls;
- IP address не всегда позволяет восстановить исходный hostname;
- exposed ENV name не доказывает, что приложение реально вызвало `getenv()`;
- lock-файл не является доказательством отсутствия вредоносного поведения.

## Работа с секретами

AmbientLock никогда не сохраняет значения environment variables. Типовые секретные
CLI-флаги (`--token`, `--password`, `--api-key`, `--client-secret` и похожие)
автоматически редактируются в поле `command`. Однако невозможно надёжно распознать
секрет, переданный как произвольный позиционный аргумент или под нестандартным именем.

Пути, IP-адреса и сами аргументы команды тоже могут быть чувствительной информацией,
поэтому `ambient.lock` нужно проверять перед публикацией.

## Сообщение об уязвимости

Не публикуйте активные секреты в issue. Опишите воспроизводимый сценарий без
ключей, токенов и персональных данных.
